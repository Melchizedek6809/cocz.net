Message Routing Architecture

I suppose the client to server part should be quite clear by now, I've pretty much implemented the design as initially thought up. The sending part has some minor tweaks, mainly regarding "routing". In order to send a message from server to client the user code needs to do a POST request to the ws2http server, so far so good. Now there are basically 2 ways in which we limit who receives the message.

1. Targeted Messages to Specific IDs

Send a message to specific ID's, this is probably the most boring one. We can set the id field, and thereby send the message only to these particular sockets. If ws2http can't find a socket it'll trigger an "ERROR" subsequent event which hopefully removes that connection from storage.

2. Broadcasting to URL Paths

Send a message to a URL: ws2http accepts every URL and stores it for each connection, we can then send a message to everyone connected to a particular URL, this also includes the search parameters, so we can implement chat rooms for example super easily. Additionally there is a field notTo where we can pass a comma separated list of sockets that shouldn't receive that particular message, probably most useful so the sender doesn't receive their own message.

Next Steps
